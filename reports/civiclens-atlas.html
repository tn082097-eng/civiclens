Part 1 — The Story

1

It begins with the public record.

Ten streams of official government records, stock trades, votes, campaign money, lobbying filings. Nothing is invented: if a source can't be reached, the system stops rather than guessing.

2

Everything converges into one database.

Every stream is cleaned up and filed into a single database. Every row of it can be traced back to the official document it came from.

3

Detectors interrogate the data.

Each detector asks one narrow question, like "did this trade land suspiciously close to a vote?" Every hit is then tested against random chance, so a coincidence can't be dressed up as a pattern.

trade-vote-alignment: A member trades a stock in the two weeks before a vote their own committee controlled, or before a bill that names the very company they traded.

spousal-trade-timing: The same timing check, applied to trades made by a member's spouse or joint accounts.

donor-sector-vote-alignment: A member writes bills in exactly the industries their campaign donations come from.

recipient-trade overlap: Built, not yet run, does a member trade stock of the specific companies winning contracts in their own district? Pre-registered null, blind confirmation. (Its theme-level predecessor tested clean against chance and was honestly retired.)

4

Evidence becomes thirteen sections.

Every member's page has the same thirteen sections. When there's no data for one, the page says so out loud, nothing is ever quietly left out. And rebuilding the site always produces exactly the same pages, so any change is a deliberate one.

5

The site is checked, then published as-is.

The finished site is built and double-checked on one trusted computer, then published to the web exactly as built, the hosting service never rebuilds or changes anything, and private keys never leave the machine.

Note: the front page only reports counts, it never makes claims

6

Now explore the whole system.

Hover to trace connections. Click anything to zoom in. Search to jump.

The thirteen sections every member page carries: identity, glance, receipts, coherence, money votes, timeline, trades, donors, revolving, outside spending, peers, patterns, cosponsor.

Part 2 — Project Status

Shipped through the publish gate

Phases: P0 complete; P1 roster complete; P2 data complete; P3 analysis complete; P4 launch complete; governance (current).

The site is live since July 9, 2026, two members published (Gottheimer + Pelosi). Since then the project spent its effort on saying no properly. The recipient-trade detector ran its one pre-registered test on July 19 and failed the gate (p = 0.74); it was published as a null result rather than tuned into significance, the second dead spine filed as a negative experiment. That discipline is now machinery, not intention: a confirmatory-run registry plus an in-path guard refuses a second run on a consumed detector, and unevidenced invalidation fails closed. Ingestion was repaired the same way, every broad loader now demands an explicit member and fails closed without one, so routine onboarding can no longer overwrite a neighbour's rows or accidentally consume the parked timing detectors' single run. Amber dots mark what is genuinely open.

trade-vote-alignment

detector, parked

Flags a stock trade made in the two weeks before a vote the member's own committee controlled, or before a bill naming that very company. Descriptive today: it can show you a pattern, but it is not yet allowed to call it significant.

Queued nownegative-control gate, awaiting authorisation, a vote-attribute scramble must show the scorer stays quiet on noise before the real confirmatory run is allowed. Parked: it needs an explicit go-ahead, and running it early would burn the one preregistered run
Filepipeline/patterns/trade-vote-alignment.ts
SignalTrade within 14 days before a vote on a bill the member's committee had jurisdiction over, or whose text names the traded company
ParkedRegistered, unconsumed. Its one preregistered confirmatory run is still unspent, held behind a negative-control gate that needs explicit authorisation
Why parkedBasket traders saturate a 14-day window mechanically: 1,900+ trades will land near some vote by volume alone. Until the null model says otherwise, hits render capped and captioned as unscored
ProtectionFiltered out of run-patterns --member entirely, so onboarding a new member can never compute its first p-values as a side effect
Writespattern_hits, then rendered in the Patterns section

recipient-trade overlap (planned or gated)

gated, published as a null

Does a member personally trade stock of the specific companies receiving federal contracts in their own district? Answer, as tested: no. Both spines were gated by their own pre-registered null and filed as negative results.

StatusRan once, 2026-07-19, GATE FAIL (a47ca81). Thread closed; the detector was never registered
ResultS1 breadth p = 0.7445, S2 exposure p = 0.3760, members traded fewer own-district recipients than chance. Negative control clean 0/20, so the null is real, not broken machinery
PredecessorThe theme-level spine failed first (p = 0.48). Two dead spines, filed as negative experiments, defense money is everywhere; named contractors are not
PowerOnly 9 of 33 members had in-window traded tickers, and 15 near-universal defence/health tickers were ubiquity-excluded. Thin power, recorded as-is rather than tuned away
HonestyPublished to the live methodology page as "Detectors we tested and rejected", the null is the finding, not a failure to hide
Left behindThe substrate stays as infrastructure: 397 hand-confirmed recipient_ticker rows (blind curation, identity fields only) + the USAspending/SAM.gov loaders. Any variant is a NEW detector with a NEW pre-registration
Filespipeline/patterns/recipient-trade-{candidates,overlap,baseline}.ts, spec docs/2026-07-17-recipient-trade-detector.md, audit trail docs/recipient-trade-curation-2026-07-18/

Confirmatory-run guard

the one-shot rule, enforced

The part that stops the project fooling itself. A detector gets exactly one preregistered test. Spend it, and the answer stands, pass or fail. This is not a convention anyone has to remember; it is code that refuses.

In-path: The guard sits inside the five baseline runners, before any DB access. A consumed detector halts the process, you cannot forget to check, because checking is not a step you perform

Filesdocs/confirmatory-runs.md (registry), scripts/confirmatory-guard.ts, ADR docs/adr/0003
The ruleOne confirmatory run per detector. A FAIL is archived as a negative result, never retuned, reseeded, or quietly re-run until it passes
Fails closedMarking a run invalidated is not enough to reopen it: without a documented evidence reference the guard still refuses. The escape hatch needs a paper trail
Ledgerconsumed-fail × 3 (both district spines, recipient-trade), registered × 2 (the parked timing pair)
Why it existsTwo detectors have already died by this rule. That is the point, a transparency project that cannot publish a null result is just narrative with a database attached

Member-scope contract

lib/ingest-scope.ts

"Onboard one member" now means one member at every command boundary. A loader with no target refuses to run rather than silently assuming you meant everyone.

Filelib/ingest-scope.ts, boundaries in AGENTS.md
ContractExactly one of --member, --bioguide, or --all. No selector fails closed, absence never means all
Identity firstA slug resolves to exactly one canonical bioguide before any network call or DB write; unknown or ambiguous fails loud rather than guessing
Blast radiusFive broad loaders made member-scoped and transactional. Two-member fixtures prove the other member's rows stay byte-identical through every affected table
Chamber branchA senator uses Senate PTRs and must not run House PFD or district loaders, no statewide substitute exists, so those are skipped, not approximated
WhyThe old default let a one-member run overwrite a neighbour's data, or consume a parked detector's single preregistered run by accident

Agent pipeline

agents/pipeline.ts

The assembly line that builds each member's profile, nine fixed steps, run the same way every time. AI writes only the narrative text; it never touches the data.

OrderResearcher, then Data Checker, then (Predictor, skipped by default), then Trade Analyst, then Summarizer, then Code Checker, then Final Reviewer
Hard stagesResearcher, Data Checker, Summarizer, abort after retry
Soft stagesTrade Analyst, Code Checker, warn + continue
GateFinal Reviewer is a pure deterministic gate (LLM call stripped)
Shrinking on purposeConnection Mapper and Revolving Door were deleted, not rewritten, both became deterministic SQL (findSharedDonors(), revolvingDoorConnections). Two LLM stages remain where three agents used to speculate
ModelsSummarizer + Trade Analyst default claude-sonnet-4-6; env-overridable per agent
RunnerDetectors run via pipeline/run-patterns.ts, --member slug for one member, --all for the roster. The member path is timing-safe: it filters the parked timing pair before any detect or write
