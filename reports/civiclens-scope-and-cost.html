CivicLens — Scope and Cost Assessment

Measured from repository evidence · 28 Apr – 26 Jul 2026 · prepared 26 Jul 2026

This assessment replaces an earlier estimate that was produced entirely from per-unit assumptions with no repository access. Every figure below is labelled Verified (counted directly from the repository or its build outputs), Modelled (inferred, with the basis stated), or Open (not determinable from available evidence). These categories are never combined into a single number.

What changed against the prior estimate

The prior estimate carried two acknowledged weaknesses. Both are now resolved:

  • No project start date was available. Now established: first authored work 28 April 2026, most recent 26 July 2026 — a span of 2.9 months. This is materially shorter than the prior estimate's implied 3.5–6.6 person-month range, which is now contradicted by calendar evidence.
  • Hour figures were never validated against delivered code volume. Now measured: 18,043 lines of production TypeScript across 89 modules, plus 2,841 lines of tests across 37 test files, with a 198/198 passing suite executed during this assessment.

Disagreements explained

Warehouse tables — 29, not 27. Queried live from data/civiclens.duckdb via information_schema. The 29 base tables are confirmed materialised, not merely declared in schema files. Views match the atlas exactly at 11.

Detectors — 3 registered, 4 implemented. The registry (pipeline/patterns/registry.ts) exports three active detectors: trade-vote-alignment, spousal-trade-timing, donor-sector-vote-alignment. A fourth, district-contract-trade-alignment, is fully built but deliberately gated out — its permutation null baseline failed (p=0.48). Both numbers are defensible depending on whether the question is "what runs" or "what was built"; the atlas figure of 4 reflects engineering effort expended, which for costing purposes is the more relevant count. The distinction should not be silently collapsed, since gated code represents delivered work that produces no output.

Governance components — 3, not 2. The repository contains docs/confirmatory-runs.md (the run registry), pipeline/patterns/_confirmatory-guard.ts (the in-path guard), and scripts/confirmatory-guard.ts (the CLI guard). These are three distinct components with separate test coverage.

Pipeline stages — not verifiable as "9". The pipeline/ directory contains three executable stage entry points (run-patterns, score-anomaly, score-theme-gaps). Project documentation describes an 8-stage pipeline following a Phase 1 reduction from an earlier larger set. Neither figure reconciles to 9 from disk evidence. This count cannot be confirmed and should not be relied upon without a stated definition of what constitutes a stage.

Source modules and dependencies — atlas undercounts by roughly 2.5×. The repository contains 89 non-test TypeScript modules (excluding fixtures and test kit) and 72 distinct internal import edges. The atlas figures of 33 and 30 appear to describe a curated subset rather than the full graph. For scope assessment the larger figures are the correct basis.

Members published — 1, not 2

The committed launch artefact public/members/ contains exactly one page: josh-gottheimer.html. render/published-members.json likewise lists a single member. Pelosi appears in the repository only in test fixtures, planning documents, and a stub-data.json file — not as a published page.

Separately, the working database holds 57 members ingested. Ingestion scope and publication scope differ by a factor of 57 and should never be conflated in external reporting.

5. Effort reconciliation

The prior estimate proposed 559–1,053 engineering hours, equivalent to 3.5–6.6 person-months. That range was built bottom-up from per-unit hour assumptions with no repository access and no known start date.

Why the prior range's upper half is now excluded

The project spans 2.9 calendar months (28 Apr – 26 Jul 2026). The prior estimate's upper bound of 6.6 person-months therefore exceeds the entire elapsed calendar period by more than 2×. Reaching 1,053 hours in 89 days would require approximately 11.8 hours every single calendar day including weekends and non-active days. Commit evidence shows work on 48 of 89 days, which does not support that intensity. The upper portion of the prior range is incompatible with the calendar and should be withdrawn.

Revised effort basis Modelled

Git records commits, not hours. No hour figure in this section is measured. The basis used here is active days × observed commit intensity, which is an inference and is presented as such. It is stated explicitly so the reader can substitute their own assumptions.

Observed structure: 48 active days across 89 calendar days; 275 commits all-branch; a mean of 5.7 commits per active day; 18 days at 5+ commits. This is the signature of concentrated working sessions rather than continuous full-time work.

Revised range: 192–384 hours Modelled, centred near 288 hours (~1.8 person-months at 160 h/month). This is roughly one-third of the prior estimate's midpoint.

Cross-check against delivered volume: 20,884 lines of hand-authored TypeScript over 288 hours implies ~72 lines per hour including tests, debugging, and revision. For data-integration work with a 198-test suite and documented statistical governance, this is a plausible-to-brisk rate, supporting the central figure as reasonable rather than inflated.

6. Infrastructure and unrecoverable costs

Infrastructure: approximately $0 Verified by architecture. The build runs locally, the site deploys as static files to GitHub Pages via a manually-triggered workflow, the database is a local DuckDB file that is never published, and all data sources are public APIs. The deploy workflow is documented as dormant by design, requires no secrets, and performs no data access. There is no server, no hosted database, and no paid service in the delivery path.

Open — Claude API spend not determinable

The repository contains agent modules that call the Claude API, but token consumption and billing are not recorded in the repository and cannot be recovered from it. No log, manifest, or usage artefact in the codebase captures spend.

This figure is left explicitly open. It can only be closed with figures exported from the Anthropic console covering 28 April – 26 July 2026. It is not estimated here, and the totals in Section 5 exclude it. Any final cost figure must add this separately.
